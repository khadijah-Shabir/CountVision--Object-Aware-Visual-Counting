# Implementation and evaluation decisions

The released evaluation uses Qwen2-VL-7B-Instruct with the model default generation settings from decision 29. Decisions 22 and 33 record earlier plans. The additional backbones in decision 26 and a clean secondary temperature comparison remain unevaluated in the active results. The answer bound in decision 38 was selected after inspecting test outputs. See the report for the complete-case Penguin and clustered Emoji analyses.

| # | Item | Choice | Reason |
|---|---|---|---|
| 1 | GroundingDINO variant | HF `IDEA-Research/grounding-dino-base` (Swin-B) | Spec default was Swin-T, but the authors' released code (`object_aware_image_divider.py`) uses `groundingdino_swinb_cogcoor`; I matched the authors. HF port (transformers 4.47.1) instead of the original repo because the original needs CUDA-compiled ops. Swin-T is downloadable for the sensitivity check. |
| 2 | SAM variant | ViT-H (`sam_vit_h_4b8939.pth`) | Same as authors. |
| 3 | Text threshold | 0.1 for both stages | Spec. |
| 4 | Samples per mask | 5 | Spec. NB: authors' code samples 1.5% of all pooled mask pixels instead; not used. |
| 5 | Cut position between clusters | midpoint of (max x left cluster, min x right cluster) | Spec. |
| 6 | MeanShift | `sklearn.cluster.MeanShift()` default bandwidth | Spec. Observed: the default (quantile-based) bandwidth can split tight integer-valued samples into several clusters (e.g. [49..52] -> 3 cuts). Replicated faithfully; unit tests check invariants, not cluster counts. |
| 7 | Morphological refinement | closing (`MORPH_CLOSE`), 3x3 square | Spec choice; authors use close then a second op with iterations=2 (not replicated). |
| 8 | Erosion | `cv2.erode`, 2x2 square | Spec: "square kernel, 2 px". |
| 9 | Excessively large masks | drop masks with area > 50% of the crop **and** > 25x the median mask area | Spec says '> 50%' (as an example). On 30 seeded FSC-147 *val* images the 50%-only rule left 44% of cuts impossible (a false-positive mask walls off the crop, verified: no free top-to-bottom route even at full resolution). The authors' code uses 25x median; adopted. See #25 for the measured effect. |
| 10 | Blank colour of sub-images | white (255) | Spec. |
| 11 | A* neighbourhood | 8-connected, unit step cost, **no diagonal corner cutting** | Needed so a straight line between consecutive nodes can never touch an obstacle. Manhattan heuristic replicated (inadmissible with unit-cost diagonals; octile-style `max(dr,dc)` available as `heuristic="octile"`). |
| 12 | A* efficiency | search on a grid downscaled so max side <= 256; a coarse cell is walkable only if *all* its pixels are free; falls back to finer scales (…,1) when no path exists | Spec 3b.4; guarantees no obstacle pixel on the full-resolution path (unit-tested). |
| 13 | Endpoint on obstacle | moved to nearest free cell on the same row | Spec. |
| 14 | Path pixels in the partition | assigned to nearest region (EDT) | Guarantees each pixel belongs to exactly one region. |
| 15 | Tiny regions | regions with area < 100 px are not sent to the LVLM and count as 0 | Avoids API calls on slivers. |
| 16 | Plural/singular | area detection uses `E` as given; segmentation uses a naive singulariser | Paper's convention; FSC-147 names are plural. |
| 17 | Zero-count handling | kept (PASCAL has 5 zero questions) | Spec. |
| 18 | PASCAL question list | the authors' released, manually corrected 102 questions (`pascal.csv`) are the primary benchmark; a seeded rebuild from raw VOC annotations is written separately (`pascal_rebuilt.jsonl`) | Spec: "if the authors' repo contains the exact list, use it". Raw-annotation agreement is in `benchmarks/pascal_agreement.json` (authors' GT equals raw VOC count in only 43/102 questions, i.e. their manual correction changed many). **Must be manually verified by a human.** |
| 19 | VOC "difficult" objects | counted in the rebuild | Logged; authors' GT matches this convention more often than excluding them (43 vs 28 of 102). |
| 20 | Penguin ground truth | `max` over annotators (`penguin.csv` column) | Spec. `penguin.csv` == the separate-site TEST split (21,736 images, verified against `imdb_sepsites.json`). |
| 21 | Penguin sampling | 100 images, p ∝ 1/frequency(GT value), seed 1234 | Spec. Sampled from all test images available locally (extra sites downloaded to `datasets/penguin_full/`). |
| 22 | LVLM backbone | Claude (user-approved) in place of GPT-4o / Gemma 3 / Qwen2-VL | No OpenAI key; user said a Claude model is OK. Replication numbers for the paper's backbones are therefore *not* reproduced; Claude rows are new. |
| 23 | Sampling temperature | provider default | Spec. |
| 24 | MeanShift run on x only | yes | Spec (vertical-only main setting). |
| 25 | Group-box filter before SAM | drop 'group' boxes: largest-first, a box is dropped while it covers > 67% of the MBR of all smaller boxes (replicates `filter_bboxes` in the authors' `grounded_sam.py`) | Not in the paper's text, but present in the authors' code and decisive in practice. Measured on 30 seeded FSC-147 val images (`results/val_cut_diagnostics.json`): cut-failure rate / images with every cut failed — none: 44.3% / 9; 25x-median only: 36.1% / 8; group filter only: 22.2% / 4; **group filter + 25x median: 15.6% / 3** (adopted); group + 10x: 14.8% / 3. Chosen on validation only; test sets untouched. Remaining failures are mostly touching objects with no free gap (the paper's stated limitation). |
| 26 | LVLM backbones | Qwen2-VL-7B-Instruct, Qwen2.5-VL-7B-Instruct, Qwen2.5-VL-32B-Instruct (fp16, HF transformers) | No paid API (user: use open-source free HF models). Hardware is 6x Tesla V100 32GB: no bf16, and AWQ kernels need sm>=75, so the paper's Qwen2-VL-72B-AWQ cannot run; fp16 72B (~144GB) is impractical. Gemma 3 27B is gated and the HF account has not accepted its licence. Numbers are therefore NOT comparable to the paper's backbone columns. |
| 27 | Precision / attention | fp16, `attn_implementation="sdpa"` | V100: no bf16 hardware, no FlashAttention-2. |
| 28 | Lenient answer parsing | strict spec regex `\[\[(.+)\]\]` first; if absent, accept a reply that is *only* a number/number-word, optionally in single brackets (`[5]`, `5`, `five.`); everything else is retried (cap 10) | Pilot (Qwen2-VL-7B, 100 FSC-147 val images): 55% of jobs failed the strict regex at least once (model answers `[5]` or `0`) and 3.5% exhausted 10 retries and would silently count as 0. Applied identically to base and every LVLM-Count variant. Strict-regex failures are still counted per job (`strict_failures`) and reported in the parse-failure table. |
| 29 | Sampling (REVISED) | **main regime = the model's shipped `generation_config.json`** (Qwen2-VL / Qwen2.5-VL: sampling on, temperature 0.01, top_p 0.001, top_k 1, i.e. near-greedy), same for every method. Secondary regime `_t1` = pure sampling T=1.0, top_p=1, no top-k (authors' CLI defaults) | First choice was T=1.0 (see #33). It was **revised after the full FSC-147 test run showed absurd outputs** (single answers up to 7e9 giving MAE in the millions) caused by untruncated sampling on a 7B model. To avoid selecting on test data, the revision was decided on the 100-image FSC-147 *val* pilot (3 trials each): default regime MAE base/full/naive3 = 44.2/36.2/43.4 with identical trials; T=1.0 = 118.9/58.5/107.9 with trial MAEs 62-221 dominated by outliers (median abs. error 12 vs 11). The T=1.0 test results of the first run were discarded (they also suffered bugs #35/#36) and are re-run in the secondary regime. Consequence: trials are near-identical in the main regime, so trial-level CIs are ~0 and uninformative; uncertainty is reported with the paired bootstrap over images. |
| 30 | Sliver sub-images | kept; tiny rule remains area < 100 px | Pilot check on val: 22% of full-variant sub-images have a side < 16 px but the LVLM answers 0 for 20/22 of them; dropping slivers of any size up to 32 px moves MAE by < 0.2. No rule change (avoid tuning to noise). |
| 31 | Penguin unlabeled images | the 1,649 test images with an empty annotator list (`number_vector=[]`, `max=NaN`) are excluded before sampling | No ground truth. Remaining GT range 0-213 as in the spec. |
| 32 | Job sharding | job list is shuffled (seed 1234) before sharding | First small run sharded `jobs[i::6]` over a trial-ordered list, so a single OOM-crashed shard deleted a whole trial (found and re-run; no result was dropped silently). |
| 33 | Second sampling regime | secondary runs with the model's own generation-config defaults (Qwen2-VL: temperature 0.01, top_k 1, top_p 0.001 = near-greedy) reported separately as 'model-default sampling' | The main runs use T=1.0 (decision 29). A 7B model at T=1.0 hallucinates large counts (e.g. median 23 but p90 115 and max 1414 for Emoji base, where GT is 30-50), which widens CIs; the near-greedy regime shows how much of that is sampling noise. Near-greedy trials are almost identical, so their CIs are not informative. |
| 34 | SAM 'segment-everything' variant (ablation row 5; penguin SAM-only) | `SamAutomaticMaskGenerator(points_per_side=32, pred_iou_thresh=0.86, stability_score_thresh=0.92, min_mask_region_area=100)` as in the authors' code, but **`crop_n_layers=0`** (authors: 1) | Speed: crop layers multiply SAM cost several-fold per image. Mask NMS uses predicted IoU as the confidence; same post-processing and median-area rule as the main variant; no group-box filter (no boxes exist). |
| 35 | Degenerate-image padding | before the LVLM, every input image is white-padded so min side >= 56 px and aspect ratio <= 8 | Qwen's processor raises `absolute aspect ratio must be smaller than 200` and needs >= 2 patches per side; in the first run these batches silently returned empty answers. Content is unchanged; applied to every method incl. base. |
| 36 | Parser overflow bug | `parse_count` treats `1e999`/inf as a parse failure | First FSC-147 run: 3 of 5 workers crashed with `OverflowError` (found from the missing-job count 37,560/195,000, re-run in full). |
| 37 | Trials per variant | main table methods (base, full): 6 trials; ablation variants (naive, area_naive, area_only, no_area, sam_all): 3 trials | Near-greedy default sampling makes trials nearly identical (pilot: 44.2 / 44.2 / 44.2), so extra trials add compute, not information. A stated reduction relative to the spec's 6. |
| 38 | Plausibility bound | a single LVLM answer > 10,000 is an invalid answer: counted as 0 and flagged (`n_implausible`); raw predictions are kept (`pred_raw`) and every table also lists the unfiltered MAE | In the main FSC-147 run 22 of 127,278 answers were >= 10,000 (e.g. `[[659135152]]`, identical across trials, on 3-4 very dense images), which made the base MAE 553,930 and swamped every comparison. The bound was set above the benchmark count range after inspecting the test outputs and was applied identically to all methods; re-asking cannot help because near-greedy decoding reproduces the same answer. Chosen after seeing the test run, so unfiltered numbers are reported alongside. |
